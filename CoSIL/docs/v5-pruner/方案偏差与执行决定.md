## 独立记录的小数据探索性实验

用户已要求后续决定自主处理至实验结束。若 30 条训练样本证据审阅通过，且除正例数量外所有质量门均通过，继续执行明确标记为 **exploratory（小数据探索性）** 的双底座训练。原正式条件与探索性条件在报告和输出目录中分别标识；这不是原方案规模要求已达成。

首版冻结的数据为正例 1,542、负例 3,084，共 4,626 对；其中 E 负例去重并集 3,000，满足原 E 数量门。按 issue 固定切分 240/30/30，对应训练 3,924 对、验证 363 对、测试 339 对。**首版样本审阅随后失败，不能用于训练**。测试集继续封存，训练与模型选择只用训练、验证集。

E 数量目标与 1:2 配比同时保留后，D-only 负例仅 84 对；负例中另有同时带 D 来源证据的样本，不能把重叠来源计数相加当独立样本。这种构成与常规函数的总体分布不同，报告需列出各来源及重叠，不据此宣称对所有负例有效。

探索性执行决定须绑定审阅后的完整统计、切分、数据封存、训练/验证文件及协议快照的 SHA256。只允许 `positive_unique_pairs_ge_8000` 这一数量门失败；审阅、去重、泄漏、标签来源等要求不豁免。底座、LoRA 配置、验证资格线和测试一次开箱规则沿用方案。没有通过模型资格线或金丝雀门时，记录失败并产出报告，不编造后续全量结果。

## 首版审阅发现漏过滤，先修复再训练

机械检查器验证了 30/30 条来源与冻结图的一致性，但这不等于标签质量合格。源码和 issue traceback 至少证明 3 个 E 负例属于 gold 的调用链：

| issue | 被标为 E 负例的函数 | 证据中的 gold 调用 |
|---|---|---|
| django__django-14667 | QuerySet.defer | `clone.query.add_deferred_loading(fields)` → Query.add_deferred_loading |
| django__django-16255 | sitemaps.views.index | `site.get_latest_lastmod()`；traceback 进入 Sitemap.get_latest_lastmod |
| matplotlib__matplotlib-23964 | Text.draw | `textrenderer.draw_text(...)`；traceback 进入 RendererPS.draw_text |

这些属性调用未满足唯一静态绑定要求，因此没被原图纳入；若仅依据“图中没有边”判断无因果关系，便会漏过滤。首版审阅记录为至少 3/30 错误，超过 ≤2 的门槛；训练未启动。最初按机械规则一致性签为 0 错误的记录已保留，另存纠正记录并将质量门改回失败，原标签与数据文件字节均保留。

修复方式是增加**保守排除**：对负例恢复完整 base 函数源码；凡候选可能调用 gold，或 gold 可能调用候选，以及 issue traceback 明确包含 gold 与候选的调用链，均排除该负例。歧义名称命中不新增调用图真边、不生成 C 正例、不翻转标签。无 base-existing 函数 gold 的题目无法完成这一函数关系核对，其负例保守排除。使用原 candidate pool 与同一 issue 切分生成独立版本，重新冻结、重新抽取 30 条训练样本审阅；不读取旧 test 的性能、不拼接测试预测。

在任何真实模型预测之前，确定 **v3 为本次数据修复的最后一轮**：保留原随机种子与 issue 切分，统一规则重构，再完整审阅 30 条。若仍超过 2 个有证据的标签错误，或有非数量质量门失败，按计划止损点结束并产出失败报告。不会继续换抽样、逐题人工筛删或豁免质量门以凑出通过结论。仅在 v3 的非数量门均通过时，才执行明确记录的小数据探索性训练；测试开箱和全量仍受后续门槛约束。

## 输入信息限制

正例的调用关系标签来自完整静态图，但模型仅见 issue 前 2,000 字符及候选函数前 1,500 字符。独立只读审计表明，train 的 C 正例中 521/1,053（49.5%）、val 中 71/87（81.6%）在候选输入中没有完整的显式直接调用证据：一部分调用发生在未提供的 gold 源码，一部分落在候选源码截断之后。这是输入信息与训练／验证分布差异，不能据此判标签错误。本轮不改变输入字段或截断长度；其影响需要结合真实训练结果解释。[逐对可见性审计](../../results/v5_pruner/data_input_visibility_audit.json)保留证据。

## 已确认的口径修正

- 金标沿用真实 patch 改动行＋前后 AST；hunk 头只审计。历史 off 基线为 111/293（37.88%）。
- E 主指标为正确剔除率 `TN/(TN+FP)`；另报混合集剔除 precision `TN/(TN+FN)` 和 gold 保留召回。
- 缺少原 PPR 邻接，按 base commit AST 重建带调用点证据的直接调用图。C 只取一跳；已知多跳关系从 E 中排除。静态图无法完整表达动态调用、数据依赖或真正因果关系，标签是机械代理信号。
- 取消 Decision-1。仅在同一真实已查询函数对上比较本地裁判与历史 Qwen 判决；`e_log` 按 Qwen=True 选择，不能把该子集的一致率当无偏能力评测。
- 30 条核验由 Codex 审阅源码、patch、图和日志证据，记录为“Codex/机械证据审阅”，不冒用人工签名，不制造标签。
- 固定分配 train240／val30／test30；本次最终有训练数据行217题，但实际梯度训练0题。全300、预定held-out60与纯test30的分层成绩属于尚未执行的评测计划；若未来有效执行，val30会参与选择与校准，需单独报告纯test30。
- ≥80% token 降幅专指大 Qwen pruner 接口的 prompt＋completion tokens；本地裁判前向输入 tokens 和两者合计另报，不能把本地开销计作零。
- 函数裁判替换只作用于函数；类请求继续调用原 Qwen，记录 class fallback。

阈值不直接照抄名义默认 0.6/0.9。真实模型训练和预测之前确定仅用验证集选择的规则：低阈值网格 0、0.05…0.60，高阈值 0.90…1.00；约束为验证 A/B gold 不直接误剪、E 不直接错留超过 5%。在满足约束的组合中先最小化灰区，再最大化 E 直接正确剔除率，最后靠近名义默认值破平。所有候选和风险均落盘；E 直接剔除 ≥85% 与灰区 ≤20% 作为报告目标，不假定灰区 Qwen 必然正确。无 gold/E 或无可行组合时记录阈值选择失败，不自动切回默认。赢家和阈值在测试开箱前冻结。这些验证约束不构成对测试集或全量定位结果的保证。

## 资源与运行恢复

保留 GPU0 的既有 vLLM 以及 GPU1 的既有进程。训练/本地裁判使用 GPU2，GPU3 保持空闲；模型下载和构图在 CPU 执行。不会启动新付费 API 或重跑全 300 题 Qwen 基线。

首次挖矿在输出最终数据前进程消失，没有 traceback，原因未确定。保存当次日志和恢复记录后，使用持久 tmux 会话从相同冻结脚本与切分重新挖矿，未改标签或拼接不完整数据。最终输出来源为恢复运行。

v3 首次实际重构发现源码证据提取很慢。只读 cProfile 定位到 `ast.get_source_segment` 反复逐字符拆分整份源码：一个实际 Table.__init__ 的摘要处理约99.6%耗时在此。增加对原 stdlib splitter 的有界缓存，保留原 `get_source_segment`、UTF-8字节列、换行及每次返回新列表的行为。两种 Python 版本的切片等价检查以及同解释器真实五链完整 canonical 输出检查均通过；实际 Python3.11 Table 的完整见证相同，原约1.165秒降至缓存冷调用约0.022秒、热调用约0.003秒。

保存慢运行的日志、状态、源码 SHA 与 profile 后，仅结束本实验自己的进程，用独立 `refine_pruner_data_v3_fast.py` 单一重启同一v3规则。原v3规则、v2辅助脚本、原挖矿器保持冻结；新版统计分别登记真实fast入口、缓存实现和原规则 SHA。此项只优化运行开销，不改标签、风险规则、切分、种子或采样，也不新增数据修复轮。
