# 配对修复中断恢复身份校验：改动前检查

2026-10-25，正式50题尚未冻结，增量API账本及模型请求尚未产生。资格检查继续运行；以下是首次付费推理前的工程审查，不是修改实验方法。

静态审查发现三个可触发的恢复边界：

1. `run.generate_arm` 可直接复用已有 `candidate_response.json`，未走 provider 对原请求和结算记录的验证；未发现现有结果实际混用。
2. `run.prepare_inputs` 对已有 `prepared.json` 主要验证目录和输入模板，未把它严格绑定到当前任务、base快照及冻结源文件。
3. 新定位前尚缺对冻结 job、R2 gold及index字节哈希的一次性预检；gold内容仍只应在定位结束后读取，预检仅验证字节身份。

本批计划只增加身份和来源校验：错误缓存必须停止，不自行丢弃重抽；合法恢复不得多发模型请求；原候选、A/B输入设计、提示词、参数、评分、预算、历史产物和封存数据均沿用原协议。响应还需绑定本题、本臂的独立 provider stage 与增量账本，不能仅凭文件名复用。prepared 输入须与冻结任务和独立干净base证据一致。

用户要求先发布改动前代码和文档。本批将在确认远端恢复点后才修改代码；修复完成后运行相关中断恢复和隔离测试，再运行全套CPU测试，并发布最终实现。旧等待模型主控须在确认尚无模型请求、精确核验自身身份后替换，以加载新代码；资格父和他人进程不受影响。新主控仍等待真实50题资格门。

通过测试与发布不代表实验已经完成，最终成绩仍只取真实DeepSeek响应和正式测试回执。
