## 实现与验证边界

本批预改恢复点已发布并核验为 `fe4716725470ea713f555d5f60cdb67359663795`（tree `199d19d1ad79d5a329822f0dbf4413768695a6b2`）。代码实现仅调整镜像部署及注册表只读传输，不干扰运行中的资格父或其他进程。

配置恢复路由保留原有全部成功/失败证据格式和快照。读取时先重新验证旧证据链、donor、完整压缩层 SHA、实际 diff ID，以及原下载/loaded 回执，随后读取成功 attempt 内原 `registry_manifest_receipt.json` 并核对同源 manifest。采用该原记录调用普通离线加载逻辑，避免新调用方 `checked_at` 等采集元数据造成旧回执覆盖。实际镜像不存在时仅普通 NotFound 分支进入独立 `reload-<时间>/`，原 route、原 loaded 回执与所有原快照 bytes/mtime 不变；其他 daemon 异常原样停止。已有归档回执时不再次联网探测，小型 registry probe 和完整下载均不参与离线重载。

缓存命中返回 `new_to_daemon=False`、`loaded_by_this_run=False`、`load_performed_in_this_call=False`；本次确实完成 Docker 离线加载时仍保留新的真实所有权和加载回执。恢复 producer 首次实际加载的所有权不变。CPU 回归覆盖镜像缺失重载、不同 `checked_at` 的同源调用、原证据字节/mtime 不变、重载后缓存无所有权、producer 真加载有所有权，以及未知 daemon 错误、错源和篡改 tar 不触发加载。传输模块当前 90 项 unittest 通过。

`official_runtime._get` 仅对类型和 SSL 错误码/明确 OpenSSL reason 确认的 TLS EOF（直接或 `URLError.reason`，包括读取响应期间）做每 URL 最多 3 次 GET，总数包含首次。HTTP 401/403/429/500、证书错误、超时、其他未知错误及仅文本含 EOF 均不重试；JSON、状态/摘要和 schema 校验仍位于传输重试之外，保留原验证逻辑。原请求头、批准代理、TLS 验证和 25 秒超时均不修改。

逐次诊断使用独占创建的 `registry_get_<随机ID>_attempt_<序号>.json`，文件权限 0600，不覆盖旧记录。只记录原请求 host、URL SHA、固定阶段（anonymous_token/manifest/layer_footer）、序号、类型、HTTP 状态及开始/结束时间与成败，不存完整 URL、查询参数、headers、token、响应 body 或原异常字符串。资格调用将本轮 `folder/registry_get_audit/` 作为兼容可选参数 `audit_directory` 传入；未指定时默认本轮 `/tmp/repair50_20261024/runtime/registry_get_audit/`。

为防原始异常的 signed URL 或 Bearer 文本通过调用方 `str(exc)` 外泄，主代理明确允许最终 GET 失败统一使用安全 `RegistryGetError` 并抑制原始 traceback 展示。未知错误仍只尝试一次，原异常对象保留在进程内 `.cause`、类型保留在 `.final_error_type`，不会串入公开消息、repr 或审计；这仅调整部署诊断表达，不吞掉失败或将系统失败记为普通资格不合格。
