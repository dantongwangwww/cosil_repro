## 已完成的代码与隔离检查

代码位于 [code_repair50](../../code_repair50/)。本批新增以下功能；它们通过CPU合成测试，不代表正式任务已跑通。

1. `prepare.py`：按instance_id关联冻结265题、R2金标与干净输入；验证数据与源文件SHA，不读取历史预测来选题。种子 `20261024`，排序键为 `SHA256(UTF8("repair50-v1\0" + "20261024" + "\0" + 数据版本 + "\0" + instance_id))`，并列按instance_id排序。重复仓库仅在资格通过者之间占名额；预览中的重复不成为永久排除。
2. `locator.py`：复用论文参数版七阶段定位流程，只移除错误的metadata全局子串替换；issue、真实路径、类名、函数名及源码原样保留。历史结果按阶段核对实际请求、原始HTTP回执、请求/响应SHA、非思考状态、源码快照与AST索引；不把混合265题结果直接当统一协议结果，也不逆向“修正”旧预测。
3. `contexts.py`：A保留原上下文和原Top-10顺序，错误身份也保留；B保留A证据，只将同目标文件的片段/前缀补为完整base源码，并用白名单既有函数身份替换建议。R2范围与base源码SHA单独校验，不将参考补丁或修复后信息拼入模型输入。目标源码可见性与预测命中分开计数。
4. `input_rules.py`、`editing.py`：同一位置提示模板与严格JSON SEARCH/REPLACE协议；事务性校验后才导出diff。拒绝模糊匹配、路径越界、符号链接及评分测试修改；合法空修改独立记录。不会由Codex手工修补模型答案。
5. `statistics.py`、`reporting.py`：固定50题交付率与正式测试可判定子集分开，环境未知与模型失败分开；配对四格、精确双侧McNemar、任务级配对bootstrap（20,000次，seed 20261024）、源码与定位覆盖分组。未冻结时不输出伪百分比。
6. `official_runtime.py`：只读权限与容量预检，保存manifest/digest及大小下界。它不是已完成的正式评测执行器；目前尚未实现、验证并启动完整gold/empty资格执行集成。
