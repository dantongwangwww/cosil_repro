## 二、发现

### 发现 1：Qwen 下工具起步瓶颈仍未排除

- Qwen off：no_tool_call 8/10（80.0%）；零工具探索 3/10（30.0%）。两者分列，避免把探索后主动停止都解释为起步失败。
- Qwen on：no_tool_call 7/10（70.0%）；零工具探索 4/10（40.0%）。两者分列，避免把探索后主动停止都解释为起步失败。
- Qwen shuffled：no_tool_call 5/10（50.0%）；零工具探索 4/10（40.0%）。两者分列，避免把探索后主动停止都解释为起步失败。

GLM 旧总表的早退为 off/on/shuffled=5/10、2/10、4/10。其 2026-10-04 勘误已推翻 fetch_gold=0/1/1 的初始统计（11848 被漏检），修正后最终命中为 off 0/5、on 2/3、shuffled 1/5，仅以有最终输出的 run 为分母。来源：`实验报告_v3_节点注释三臂.md` 勘误与 `实验报告_v3_详细逐题逐臂.md`。本次不沿用旧总表的未修正结论，也不直接比较不同分母的命中百分比。

GLM 日志的 on-12907 有两条 no_tool_call，详细报告说明是同一 run 两轮停止，并非两个独立 run；事件数不能当 run 数。旧版含子 agent 与影子陪审、15/30 截断，Qwen 使用旧仓库和不同候选，跨模型差异不能单独证明“早退仅由模型造成”。

- off：零工具 run 中 3/3 的停止文本含 get_* 调用语法，说明至少部分是旧版解析/分派问题；例如调用前的 **Call 1:**、解释文字或注释会被拼入 function_name。
- on：零工具 run 中 4/4 的停止文本含 get_* 调用语法，说明至少部分是旧版解析/分派问题；例如调用前的 **Call 1:**、解释文字或注释会被拼入 function_name。
- shuffled：零工具 run 中 3/4 的停止文本含 get_* 调用语法，说明至少部分是旧版解析/分派问题；例如调用前的 **Call 1:**、解释文字或注释会被拼入 function_name。

因此本次不能证实“换成 Qwen 就消灭早退”，也不能把这些停止全部归为模型不愿调用工具。

本次没有观察到正确注释提高 gold 源码召回；维持谨慎关闭，单次小样本不能证明注释普遍无效。 正确与错配注释的总体召回和命中相同，缺乏语义特异增益；这与安慰剂解释相容，但并不能证明只有长度在起作用。 但 11/30 个 run 未启动工具，其中 10/11 明确输出了调用语法却未被分派；原计划“Qwen 下早退消失”的前提未达成，不能把本次结果视为干净的注释语义否定实验。

## 四、结论与下一步

本次没有观察到正确注释提高 gold 源码召回；维持谨慎关闭，单次小样本不能证明注释普遍无效。 正确与错配注释的总体召回和命中相同，缺乏语义特异增益；这与安慰剂解释相容，但并不能证明只有长度在起作用。 但 11/30 个 run 未启动工具，其中 10/11 明确输出了调用语法却未被分派；原计划“Qwen 下早退消失”的前提未达成，不能把本次结果视为干净的注释语义否定实验。

下一次对照应先独立验证工具调用解析器能接受模型实际输出的前缀、注释与调用名，再固定这项修正跨三臂复验。PPR 菜单等混合管线应先保证候选覆盖，再考察注释内容是否带来稳定方向增益。建议增加重复 run 与题目数；本次不声称统计显著。

## 五、局限与勘误

- 单 run×10 题；注释由 GLM 生成，质量和模型来源是混杂因素。
- Qwen 候选菜单未获原注释表覆盖的题：sympy__sympy-11400。保留原始 GLM 注释，未补生成；此类三臂初始菜单没有处理差异，不能用于证明注释语义无效。覆盖数据见 `results/v3b_annotation_coverage.json`。
- off 使用计划要求的 True/False 稳健解析，与原版并非同一算法；金丝雀差异及同服务原版对照保存在 `results/v3b_canary/` 与 `results/v3b_original_canary/`。
- 历史原版金丝雀命中 _cstack，同服务原版重跑与修正后 off 金丝雀均未复现该命中。原版重跑出现 10 次 NoneType 解析错误，修正版为 0；可确认解析故障被修复，不能把历史结果差异全部归因于该修正。温度 0.0 也不能据此假定轨迹逐字稳定。
- 错配在文件内保持注释文本集合和总长度，单个节点长度不保证相等；只有一个注释的文件无法错配，覆盖表注明；相同文本错配仍可能文本不变。
- 真值表与 hunk 上下文不一致题：django__django-10914, sympy__sympy-11400。10914 改配置变量，hunk 的 gettext_noop 是邻近上下文；11400 修复新增方法，hunk 的 _print_Symbol 也只是上下文。主结果使用用户指定真值表，附录保留 hunk 审核，未从增删 def 行重新提金标。
- 新增方法的修复前源码无法 fetch，但模型仍可能预测其名称；因此新增函数题保留在九道函数题的最终命中分母中，同时从可访问源码子集中排除。
- 按计划移除类前缀并匹配文件，避免 FITS_rec/FITS_record 拼写差异；同一文件内不同类的同名方法仍可能合并。逐题报告保留原始候选，便于核对这一宽松口径。
- 原版代码和全量结果保持不变；运行配置、输入 SHA-256、注释覆盖与实现检查见 `results/v3b_*json`。金丝雀不计入正式 30 run。
