# 最终系统排名与原始回答格式

三个系统均由同一评价器将最终提交的文件、方法标识与同一base库存和Gold比较。方法必须对应完整`path::qualified_name`及参数签名；评价器不使用Gold纠正预测，不将裸名展开成多个重载。最终排名中的无效项和重复项占据其原槽，不能借删除这些槽提升后续位置。

这里的“最终提交”需要与模型原始文本区分。CoSIL/SFPruner使用最后回答的函数序列；LocAgent按既有两样本流程，先用公开base库存解析每个回答中的明确方法身份或同文件行号，再将有效身份按MRR融合。其上游解析会去重、将无法唯一映射的项记入`resolution_audit`；这些项不参加中间MRR列表。因此，主表的k指各系统**最终输出排名**，不是不同系统原始回答中的第k行，也不能说LocAgent中间解析从未删除任何无效文字。

Java方法身份、构造函数、嵌套所属链和可核验行范围均来自修复前库存。LocAgent的签名/同文件行号解析属于Java前端适配，原始回答、解析审计、两样本结果与融合排名全部保留。该容错规则是系统协议的一部分，不代表三个系统具有完全相同的原始输出容错方式。

文件主指标限定既有生产Java文件；方法主指标限定完整、非空既有方法目标集合。125与117是这两个可评分母，分配和运行的总题数仍为128。新增方法、函数外修改及其他语言修改单独说明，运行失败不能从可评分母中删除。

这些指标衡量与参考改动位置的一致性。实验没有生成修复补丁或运行修复测试，不能把Hit解释为问题已修复，也不能凭局部相关性拒绝或最终漏排推断唯一根因。
