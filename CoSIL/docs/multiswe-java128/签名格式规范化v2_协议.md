# Java签名格式规范化v2：独立离线评价协议

正式推理进行期间，对已经完成的原始输出作不读Gold的接口审查，发现参数列表中的普通格式空格会使既有Java方法被旧输出解析器漏记。方法名、参数类型及次序没有改变，问题出在展示格式与库存规范字符串不一致。

先发布恢复点`035b1a7c62e9ac7ba395b8b0559eec6b37bdf716`，再建立独立`code_multiswe_java_signature_v2_20261117`。不修改正在运行的模型、Prompt、工具、预算或原始预测，不重新调用模型；原输出、原解析及严格字符串评价全部保留。新规则统一用于所有128题和三个系统，不根据是否命中或准确率选择版本。

## 允许的变化

- 只消除参数列表标点周围、括号边缘及左括号前不改变Java含义的格式空格；不把两个标识符`A B`粘合为`AB`。
- 不更换方法/类名、路径、参数类型或参数次序，不补缺失参数，不把一个裸名展开为多个重载。没有观察到的缺类名前缀等其他格式限制，本版不顺带修复。
- CoSIL/SFPruner逐个最终函数槽处理，仅当规范标识在公开base库存唯一存在才采用；无效和重复槽不删除、不移动。
- LocAgent只使用原终态结果已有的`raw_location`，重放冻结解析器与两样本MRR，保留原解析审计。失败sample没有正常最终回答时，不从HTTP片段中捞取新答案。规范化不改变其既有MRR去重/融合规则。

## 产物与验证

规范化程序不接收Gold或参考补丁，先建立独立派生预测view，再由原独立评价器使用相同Gold判分。派生view中的原始请求、工具及资源账引用同一批实际调用，不能再次算一次模型实验或费用。保留每项变换的前后值、库存依据、原/派生结果SHA；原始文件不覆盖。

主报告使用明确标注的《实验报告_Java128_三模型总览_规范化v2.md》，同时给出旧/新评价变化，不能用较好版本替换旧报告而不说明。文件和方法可评分母不因格式修复改变；同一题集、同一模型推理，只修语义等价标识的序列化漏记。

全部128题终态齐全、原CPU评价完成后，CPU监督器才建立`evaluation_views/signature_format_v2`并生成`reports/signature_v2_evaluation`、`signature_v2_failures`、`signature_v2_resources`。最后仍须独立核验。该版不宣称修复所有Java解析或编译器语义问题。
