# Qwen3-8B＋训练版Reranker-4B：最终独立核验

2026-11-10；20题×2臂均完成；使用GPU 2、3，现已释放；无新增训练或DeepSeek调用。

**结论：现有4B剪枝器可以接入，当前没有证据表明它提高了既有函数定位命中率；它降低了主模型token量，但当前实现更慢。暂不继续增加训练轮次，先解决文件搜索、函数身份和初始化开销。**

4B共评分103次：直接保留42/103（40.78%）、灰区55/103（53.40%）、直接拒绝6/103（5.83%）；另有10次类源码请求直接交Qwen3，绑定失败回退0次。本地4B只评分不生成文本；单次评分墙钟中位0.179秒、P95 2.524秒，非纯GPU内核时间。

## 安全与失败原因

4B直接拒绝gold身份事件0；拒绝的源码块包含其他既有gold定义的事件也为0。两臂所有来源的gold源码拒绝事件均为0。实际只有10个不同既有gold身份进入4B评分，共13次且均高分直接保留；本组17题共有20个既有目标身份。因此“零误剪”不等于所有目标都被成功搜索或被独立验证安全。

6次直接拒绝均未命中参考目标身份，但非gold函数仍可能与故障有关，不能据此宣称剪枝precision=100%或证明E类标签噪声已被消除。

17题的7道共同失败可按实际证据归为：

| 第一处可观察阻塞 | 题数 | issue |
|---|---:|---|
| gold文件未进入共享菜单 | 5 | sympy-12419、matplotlib-24149、sympy-13895、sphinx-8627、django-16820 |
| 文件在菜单，但没有提取到目标函数源码 | 2 | django-11583、sympy-13146 |
| 已提取gold后被剪掉，或已送达gold却最终全漏 | 0 | 本轮未观察到；不能外推为不存在 |

matplotlib-24149尤其明确：预测路径漏写`lib/`，验证后文件菜单为空；两臂各4次读取都失败，仍输出了函数排名，4B没有任何评分。django-11583将模块函数错误写成`StatReloader.iter_modules_and_files`，工具按真实身份拒绝，未送达gold。它们分别体现路径身份和函数归属错误，不能解释为E类噪声造成的误剪。

20题原始Top5共100个槽中，baseline有37槽、hybrid有41槽不能匹配base函数身份（包含类项、新增函数建议及错误路径／限定名；不等同于全部为代码幻觉）。本轮保留这些槽，不模糊匹配“修好”成绩。逐题原始Top5、工具错误、目标源码提取／实际送达、4B路由见[逐题证据与失败原因](逐题证据与失败原因.md)及[独立逐题CSV](逐题独立核验.csv)。

独立复核625个请求均显式关闭思考，参数一致；625份实际usage可知，无输出截断回执；逐项检查874个源码送达事件（baseline445、hybrid429）的实际请求正文及先前接受事件，全部成立。重复送达不等于874个不同函数。仅比较读到源码次数与命中，不能证明模型内部如何使用源码。

代码10项、冻结输入81项、既有保护文件180项及额外历史矩阵哈希均未变；封存test只核对stat与开启标记，不读取内容；原CoSIL上游HEAD仍为`86dacd7d18c1198ff20da64595b7f1222d93281e`。

收尾存在一项已归档的控制器错误：发送SIGTERM后，服务退出轮询的PID身份再次检查报错，未写正常stop回执；20对预测已在此前完整落盘。独立主机核验本次session全部退出、GPU2/3均无计算进程，其他既有进程保持运行。没有重跑题目或修改历史controller状态，证明保存在`shutdown_verification.json`，不能将该收尾错误写成某题模型失败。
