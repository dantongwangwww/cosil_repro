# 文件排序擂台v2：产物字段说明

全部产物位于 `results/proposal_pilots/20261017/file_ranking_v2/`。原预研二v1的产物仍在同级 `ppr/`，不可混用。

| 产物 | 含义 |
|---|---|
| frozen_protocol.json | 首个结果前冻结的代码/协议/环境、固定20条件、8特征及300个已有种子JSON哈希 |
| cases/ISSUE/meta.json | repo/base commit、按路径排序的全部Python文件files、gold文件、种子ID、原CoSIL候选、来源SHA |
| cases/ISSUE/features.npz | X为每候选文件一行的8列特征；y为本次公开Lite文件gold监督标签；BM25/PPR_max/PPR_sum为原始基础分 |
| cases/ISSUE/content_vectors.npz | 仅文件内容的L2归一化TF-IDF稀疏矩阵，行与files一致 |
| cases/ISSUE/retrieval_rankings.npz | BM25/PPR-max/sum/随机及6个MMR条件的完整排名，数组是files的**零起始索引** |
| cases/ISSUE/LTR_OOF_probabilities.npz | LR/GBDT含/不含PPR四版的OOF相关概率，行与files一致；该题所在repo不在对应模型训练仓中 |
| cases/ISSUE/LTR_rankings.npz | 4版LTR和6版LTR＋MMR的完整排名，同样为零起始索引 |
| cases/ISSUE/*_top20.json | 便读的前20文件列表；**MMR条件中的score保留其基础检索分/模型概率，并非每步MMR边际目标值**，顺序以列表为准 |
| grouped_fivefold_manifest.json | 每折全部训练/测试仓与issue ID、行数、固定特征及拟合警告；所有300题恰好一次OOF |
| independent_planned_repo_folds.json | 全量提取和拟合结束前另行核对的同仓五折，用于事后核对实际分配 |
| fold_models/ | 本次CPU LTR模型与训练折缩放器；留服务器，不上传GitHub |
| per_issue_metrics.csv | 300题×20条件的@1/5/10/20、MRR、MRR@20与首个gold排名 |
| summary.json / final_audit.json | 全条件汇总、成功线、配对区间、完整排列/OOF/历史输入一致性核验 |

完整排名可按如下方式读取（需在CoSIL根目录执行）：

```python
import json
import numpy as np
from pathlib import Path
p = Path('results/proposal_pilots/20261017/file_ranking_v2/cases/astropy__astropy-12907')
files = json.loads((p / 'meta.json').read_text())['files']
ranking = np.load(p / 'retrieval_rankings.npz')['BM25']
ordered_paths = [files[int(i)] for i in ranking]
```

MMR在完整候选集合选前20，其后按基础排名顺延；本次MRR使用这个明确的完整排名，另有MRR@20可核对。随机精确期望作为参考，不是另行挑选的随机seed。CoSIL旧候选最多5项，超过可用长度不补造名次。

LTR训练/测试折指本次授权的公开Lite300文件标签分组交叉验证，**不代表打开既有pruner_test**；后者一直只检查文件stat和打开标记，不读取、哈希或评分其内容。
