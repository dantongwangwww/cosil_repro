## 直接复算已交付结果

以下命令使用本地真实冻结产物，分别输出新的独立主指标/资源回执和正确风险表；不会改写`cumulative560`或预测。示例输出名如果已存在，应换一个未使用名字。

```bash
ABLATION_ROOT=results/locbench_qwen3_sfpruner_ablation_20261117_preflight_v2
.venv-v5/bin/python -B \
  "$ABLATION_ROOT/audits/independent_prefix_v1/audit_prefix.py" \
  --root "$ABLATION_ROOT" --n 560 \
  --out "$ABLATION_ROOT/audits/checkpoint560/independent_reproduce_1.json"
.venv-v5/bin/python -B -m code_locbench_ablation_risk_v3_20261117.analysis \
  --root "$ABLATION_ROOT" --n 560 \
  --out "$ABLATION_ROOT/reports/risk_revision_v3/reproduce560_1"
```

前者先核REPORT_COMPLETE、全部三臂group、机器协议到controller派生协议链，再读同前缀Gold，并从原始预测槽位/HTTP/RPC重算指标、配对区间与资源。后者先精确核cache/base定义范围和原源码SHA，再判Gold，未知不当非Gold。只能对已封存的100/200/300/400/500/560前缀运行。

默认主审计只核实际消费的文件。需要最终全authority字节检查时，可另用新输出并显式加`--final-authority-rehash`；仅560允许此选项，会读取约62.1GB的冻结来源，通常无需反复执行。本轮该检查已经通过。它不包含论文/矩阵/ML封存test全部资产；另见`audits/final_scope/history_paper_matrix_sealed_integrity.{json,md}`的覆盖范围，不能泛化成全文件系统字节保证。

**不要使用旧`route_risk.json`的Gold字段。** 原封存producer把`path::name@def_line`直接与canonical Gold比较，造成假零。主定位和资源仍有效，但风险必须用上述独立v3输出。主报告、原预测与原错误表均保留，不事后覆盖。类送达和最终排名也不能由一个直接拒绝事件替代。
