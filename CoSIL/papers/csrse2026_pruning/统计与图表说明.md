# 论文统计与图表说明

本批分析只读取已结束的 Rebench100 运行及已存的 487 条验证集预测，未调用模型、训练、读取封存 test 或改写历史结果。默认复现入口只读取本目录派生数据，不依赖服务器上的原始日志。

## 可复现命令

从 CoSIL 根目录运行：

```bash
.venv-v5/bin/python papers/csrse2026_pruning/scripts/analyze.py
.venv-v5/bin/python -m unittest discover -s papers/csrse2026_pruning/tests -v
```

若要在持有历史产物的服务器重新提取派生统计：

```bash
.venv-v5/bin/python papers/csrse2026_pruning/scripts/analyze.py --extract-local
```

后一个命令读取脚本中固定白名单：Rebench100 的 paired_results、delivery_analysis、continuation_independent_audit、deployment；100 个选中 issue 的 hybrid events；所选 epoch1 的 **val_epoch_1.jsonl**。不存在扫描整个 results 或 train/test 目录的步骤。`data/provenance.json` 保存每个读取文件的相对路径、字节数和 SHA256；所有统计与图都写入本论文目录。

## 本次新增离线发现

| 数据范围 | 低阈值 | 直接处理 | 灰区升级 | 目标直接剪除 |
|---|---:|---:|---:|---:|
| 验证集487条（76条gold） | 部署low*=0.1294756772 | 312/487（64.07%） | 175/487（35.93%） | 0/76 |
| 验证集487条（76条gold） | 0.6 | 368/487（75.56%） | 119/487（24.44%） | 11/76（14.47%） |
| 运行时652次（73次gold） | 部署low* | 323/652（49.54%） | 329/652（50.46%） | 0/73 |
| 运行时652次（73次gold） | 0.6 | 448/652（68.71%） | 204/652（31.29%） | 4/73（5.48%） |

固定运行时评分下，保守阈值将125次原本会直接剪除的访问转交主模型，其中包括4次gold访问。这提供了“把不确定候选送去进一步判断”的具体过程证据。它不等价于多定位对4题：同一函数可以多次访问，升级后的主模型也可能拒绝候选，整条搜索轨迹在实际改变阈值后可能不同。

验证集零直接剪除是阈值构造的结果：`low* = nextafter(min calibrated gold probability, -inf)`。运行时零直接剪除来自冻结阈值下的实际观察；覆盖范围为57/117个不同目标身份、73次访问。运行时非gold函数可能是相关辅助函数，因此没有把非gold当作真负标签，也没有计算虚假的运行时剪除precision。

## 核验

7项CPU单元测试重算固定100题／100仓、92个函数分母、99完整配对、两臂命中四格、时长及共享文件token、652次路由、阈值边界、单调性、43题失败分布及既有独立审计计数。实际通过7/7。脚本没有修改分母、预测结果或运行参数。
