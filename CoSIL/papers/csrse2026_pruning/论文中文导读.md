# 论文中文导读

英文标题：**Collaborative Pruning with Primary and Auxiliary Models for Code Localization Agents: A Reliability Evaluation**  
中文标题：**面向代码定位智能体的主辅模型协同剪枝方法与可靠性评测**。

论文的研究问题是：**能否把部分函数相关性判断交给较小模型，同时明确记录关键源码是否被保留、哪些判断需要升级，以及这些动作最终如何影响定位？**

文章以函数证据的可靠处理为中心。TRACE是本文对实际集成层的命名：Traceable Relevance Assessment with Conservative Escalation，意为“带保守升级机制的可追溯相关性评估”。主模型使用Qwen3-8B，局部判别使用已训练的Qwen3-Reranker-4B。

## 剪枝的双重作用与训练来源

剪枝通过反馈引导搜索离开被拒绝节点及其调用分支，同时控制哪些源码进入上下文。辅助模型用Lite与Verified非重叠部分的8556个issue—函数对训练，验证487对；PyTorch/Transformers/PEFT冻结4B基座、只训练LoRA，复用epoch 1。详细来源、标签和超参数见正文第3.3节。

## 三项设计贡献

**1. 把函数判断放在明确的源码入口。** 工具找到代码后，先确认路径、限定名与base源码身份，再送入同训练格式的相关性评分器。源码提取、评分、向主搜索agent送达，分别记录，避免只看到一个函数名就认定模型已经检查过它的实现。

**2. 为不确定判断保留升级通道。** 高分直接保留、低分直接剪除、中间交给原主模型。低阈值根据既有验证集目标函数分数确定，并在Rebench实验前冻结。类别请求与无法绑定的函数也走原主模型接口。其作用是把局部确定判断与进一步评估分开。

**3. 将局部保护与全流程结果连起来评价。** 同时报告直接处理比例、实际遇到的目标函数范围、目标直剪、最终命中、token和时间；失败分析沿文件选择、函数检索、源码送达和最终排名展开。这样可以看到一个组件真正接触过哪些问题、在哪个环节有作用。

正文引用温度校准、选择性预测与多模型路由的已有研究，突出它们在代码定位源码入口的组合设计和可核验实现。

## 中文摘要

仓库级代码定位智能体需要在有限迭代次数内搜索大量函数，并持续管理进入推理上下文的源码。相关性判断因而具有双重作用：引导搜索离开无关分支，以及抑制无关代码对有效证据的干扰。本文提出主辅模型协同函数剪枝方法TRACE，将训练后的轻量相关性判别器集成到CoSIL的工具执行与上下文管理环节。辅助模型根据issue、函数源码及调用邻居进行评分，通过校准后的双阈值直接处理明确案例，并将不确定案例交回主模型；主模型继续负责搜索规划与最终定位。函数身份校验和结构化证据记录连接检索、剪枝、源码送达与最终排名，使局部决策及其作用范围可以追溯。在100道SWE-rebench任务的配对实验中，主模型相关性判断token减少38.02%，两组在92道函数可评价任务上的Hit@5均为49/92。该方法为代码定位智能体中的判断分工与可靠性评测提供了可复现的实现路径。

## 核心结果及讲述顺序

| 论文关注点 | 真实结果 | 对应意义 |
|---|---|---|
| 判断替代 | 323/652次直接处理，49.54% | 小模型实际承担了近半数已评分判断 |
| 主模型判断负担 | 判断token减少38.02% | 该组件在接入环节形成了可测量的替代效果 |
| 观察到的目标保护 | 目标访问直剪0/73；覆盖57/117身份 | 局部保护结果有明确的作用范围 |
| 函数定位 | Hit@5两组49/92，53.26% | 配对运行中的总体Top-5表现相同 |
| 全流程资源 | 主模型token少4.65%；在线均时34.89→40.07秒 | 分别评估判断替代和运行成本 |
| 失败分布 | 每组43个miss中30个未选中目标文件且未读目标源码 | 证据链能定位后续应改进的流程环节 |

新增离线分析提供了一个具体的机制结果：在同一组652次已保存分数上，使用部署低阈值而非0.6，会将125次直接剪除改为交回主模型，其中包括4次目标访问。它解释了保守升级如何分配额外判断机会。此分析是分数回放，不能等同于新增在线试验或“救回4道题”。
