# 执行与补充审计要求

本轮依照用户2026-10-21的v1.2执行方案，仅执行P0五题冒烟与P1五十题开发对照。测试封存和后续阶段授权边界不变。

用户补充要求：

1. 每组报告单题耗时与累计输入/输出token的平均值、中位数、P25–P75、P95，说明通常区间；文件选择、规划/检索、导航、裁判、最终排名分阶段。成功完成与全部已执行分开，不把失败和未运行混为一谈。
2. 模型加载、CPU构图、传输重试、队列等待须单列可测量范围。客户端请求时延含网络与服务端排队，无法凭客户端日志再拆成纯模型计算，不能猜测。恢复运行重放的前序请求另报，不将续跑用时冒充完整流程。
3. 对DeepSeek和Qwen的CoSIL工具链逐层审计：模型原文→解析/别名归一→参数是否指向有效文件/函数→是否真的执行→返回值是否为所需源码/目录→裁判和搜索agent分别是否收到。
4. 报告每题工具调用和成功次数、参数/工具错误、重复调用、提前exit；错误案例保留原始调用、实际返回及失败原因。隐式框架读取文件导入行，与模型主动调用函数源码工具分开。
5. 原CoSIL主要使用文本工具调用，经AST白名单解析后执行，不是API原生tool_calls。不能把“模型说用了工具”统计成真实执行。

已确认的工程修正与归档：

- 修改前代码/文档备份：dc92d99，完整blob核验562文件；初版新增代码/提示词备份：851a071，仅25个代码/提示词/说明文件，不含结果CSV、日志或数据。
- v1冒烟隔离挂载遗漏结构解析模块、临时目录不可写；全部失败和付费响应保存在原run，v2仅修复挂载、临时空间及HTTP连接复用。
- v2所有先前付费请求按相同请求SHA重放，30个文件选择/规划响应不再收费；费用账本继承，阶段仍合计受10美元上限约束。
- 冒烟发现UTF8字节上界用于400K token门过于保守：一个76,185个参考上下文token的请求，被按343,197字节预约，提前拦截。后续只修正分词计量，400K/10美元/每题1.5元门槛不变；使用官方V4分词器先对已保存usage做独立核验，不依据定位命中率改设置。修复前代码先发布备份。

官方计量依据：[DeepSeek Token Usage](https://api-docs.deepseek.com/quick_start/token_usage/)。模型返回usage为最终记账依据，离线分词用于请求前保留token余量；费用仍用保守上界，未知计费失败保留额度。
