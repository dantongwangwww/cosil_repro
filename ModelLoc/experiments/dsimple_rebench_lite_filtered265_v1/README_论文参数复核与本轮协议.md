## 原论文给出的设置

依据本地论文第3页算法1、第4页正文、第12页附录B：

- 五份独立文件定位，盐化哈希指定两个交集角色、一个回退角色、两个仅做一致性分析的角色；无固定五文件装入上限，也不额外强制Top10文件数。
- 路径清单按issue与固定问题的不同标识符重合数h及h/n排序；按bytes/3近似路径token，预算为全部路径估计token数与32K中较小值的一半，入选后按字母顺序展示。忽略node_modules/vendor/dist/build/target/.next目录。
- 最多四个类型化检索请求；每个可变成最多八个固定字符串；每个请求最多引入两个新文件，证据文件总共最多八个。先确定检索证据集合E，再执行预算组装，不能在超预算时通过更换后续命中文件改变E。
- 每个选中文件保留前60K o200k tokens，每个证据片段保留前12K；两种限制均逐块执行。来源标题计入上下文；按主文件后证据的顺序逐块装入，某块加入后超过80K则整块跳过。不能把证据合计限12K，也不能用最多五个文件代替token预算。
- 文件定位输出上限6,144，检索规划4,096。论文补丁输出上限32,768，但本实验不生成补丁，不能把它称为论文的函数输出上限。
- 论文使用GPT-5.6或Claude Opus 5、medium推理强度及供应商默认采样；上下文使用o200k计数。论文未给每题累计400K限制。
