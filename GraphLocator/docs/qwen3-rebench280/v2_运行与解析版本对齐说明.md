当前正式目录为`experiments/qwen3_rebench280_v2_20261115`；协议`graphlocator_qwen3_rebench280_goldblind_compat_v2`已在本轮推理前冻结，SHA256：

v2在独立outputs中对相同固定20题统一重新执行；selection/public/private/service链接复用v1已核验资产和自有Qwen3服务，不复用v1预测，不按题选较好版本。本文只描述已冻结配置与工程事实，**尚不报告未完成的v2定位成绩**。v1的[首轮结果](金丝雀20_v1_首轮结果与协议问题.md)、原始输出、自动报告和独立审计均不回写。

## 三项变化与真实时点

| 项目 | v2规则 | 记录时点与边界 |
|---|---|---|
| generation等待 | HTTP180→600秒；tokenize120秒、单题1800秒不变 | 在v1正式Gold评分前按已观察超时登记 |
| relevance输出 | 相同issue、候选、顺序，一次请求输出精确N项JSON bool数组；schema由N决定 | 同样在v1评分前登记；保留严格客户端校验，无语义重抽 |
| 公开身份库存解析 | 所有题统一由CPython3.12解析公开base定义 | 在v1成绩已观察后、v2冻结/点火前补充；依据全公开源码的语法版本证据，不伪称原来仅两项，也不伪称此项在v1评分前预登记 |

最初两项处方记录为v1 `audits/v2_prescription_before_gold_scoring.json`（UTC15:23:39）。第三项额外修订记录为v2 protocol的`additional_pre_full_parser_amendment`（UTC15:38:10），明确写明当时v1指标已可见；v2冻结为UTC15:41:26。新增解析规则对所有280题一致，不按Gold、预测正确与否或某个目标函数选择文件。

没有新增CIG词法修补：无Gold合同审计中引号/br可无损挽回为0，模型复制prompt示例、缺ID或缺Code Elements不能当parser修复。GraphRDFS图、issue和候选源码原字节、原CIG算法/prompt/排序、模型、非思考、temperature0/n1、8192输出上限、65536容量、Search5/top5及原Causal最多21次实际更新均保持。上下文超限仍明确失败，不因等待600秒而扩大上下文或静默裁源码。

## AST预检做了什么、没有做什么

| CPU步骤 | 实测规模 |
|---|---:|
| CPython3.11扫描的公开Python文件 | 67,451（280仓/题；535,888,778字节） |
| 3.11解析失败 | 687文件，涉及22题 |
| 仅失败子集交给3.12复检 | 687文件 |
| 3.12恢复 | 632文件，分布于5仓 |
| 在该失败子集中3.12仍失败 | 55文件 |

这不是“全部67,451文件都完成3.12预检”，3.11成功的其他文件在该CPU预检阶段没有重新用3.12遍历。该分析不读取Gold或预测，不改源码、不做源内容的重复全量hash、不执行仓库代码；恢复说明语法兼容性，不能推断恢复文件是正确目标或必然提高定位。

实际v2每题运行时则统一使用`/usr/bin/python3.12`（3.12.3）解析该题每份公开Python文件，`tokenize.open`后`ast.parse`，仅输出相对路径、限定名及定义范围等标准化库存。GraphLocator主环境仍为Python3.11.17；新增`public_ast.py`以`-I -B`隔离调用，不导入或执行仓库代码，不回退3.11。缺解释器或helper异常会保留失败，不偷换解析器。库存只用于把原CIG节点标准化为函数身份，不替模型增补候选或利用Gold消歧。

真实bwrap中的3.12挂载/版本/helper测试已通过，回执在v2 `audits/ast312_mount_probe/`。55项冻结运行代码/grammar均已SHA绑定；71项CPU测试整套通过。首个定长bool synthetic smoke只有一次请求、58token，独立记工程账，既不是v1/v2题目，也不计定位准确率。

## 运行与评价

服务复用同一通用Qwen3-8B固定revision，实际GPU2＋3；本轮不用DeepSeek或其他付费API。完整参数、grammar另取及隔离说明见[包README](../../rebench_qwen3/README.md)。约63MB grammar二进制、权重、数据、日志和JSON/CSV均不在公开代码快照内。

```bash
source .venv/bin/activate
python -m rebench_qwen3.controller \
  --run experiments/qwen3_rebench280_v2_20261115 --phase pilot20 --workers 2 --runner-timeout 1800

python -m rebench_qwen3.evaluate \
  --run experiments/qwen3_rebench280_v2_20261115 --scope pilot20 \
  --output experiments/qwen3_rebench280_v2_20261115/reports/pilot20_NEW
```

评价须全部scope终态后才打开离线Gold/库存/历史预测；未完成只报告进度，不算临时命中。正式报告的四臂均按同scope的20或280题投影，所有失败保分母，不把v1首轮与v2拼成更高成绩。GraphLocator原CIG单轨迹与LocAgent两样本MRR预算不同；父池有事后结果选择，不能表述为独立盲测或逐字官方复现。

[前两题v2真实协议核验（本地）](../../experiments/qwen3_rebench280_v2_20261115/audits/first_two_v2_protocol_audit.md)只验证请求/输出schema、解析器与隔离边界，不读取Gold或计算命中率；不把它当成完成20题的效果报告。


## 大仓CPU构图的独立恢复

全280题CPU预备首次得到279个成功图；HA仓有13,658份Python文件，纯CPU构图1800秒只推进至约36%而超时，模型调用为0。原v1失败回执的原路径和字节保留，没有将失败改成成功，也没有据定位表现换题。

执行器另建`experiments/qwen3_graph_cpu_timeout_retry_20261115`，同一builder与snapshot，仅将该CPU预备预算改为10800秒。v2的`public_overlay`只使HA当前readiness指向独立重试产物；其余279图与回执、全部tasks/snapshots仍链接原件。固定前20题实际输入字节不变，名单、源码、模型1800秒预算、65536上下文和检索/CIG算法不变。此处不是增加模型重试、扩大模型预算或复用更好预测。

恢复依据在本地[v2/audits/graph_cpu_timeout_recovery.json](../../experiments/qwen3_rebench280_v2_20261115/audits/graph_cpu_timeout_recovery.json)。该动作只恢复预备吞吐，不预设模型定位成绩。新复现可在新目录为CPU图准备直接使用`prepare --timeout 10800`，而推理仍为`controller --runner-timeout 1800`，不必复制本次短预算超时历史。
