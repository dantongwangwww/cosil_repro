# GraphLocator + Qwen 适配v2：部署与修复记录

本轮在 `GraphLocator/qwen_adapt/` 独立实现，原 `search_agent.py`、`causal_agent.py` 及历史预测不覆盖。当前已完成金丝雀、90次开发对照和冻结B2全量300题，正式结果以冻结清单和最终报告为准。

## 已实现的适配

- `common.py`：稳定代码ID采用限定名称加 base commit、路径、类型、位置的哈希；源码分批且保持单节点完整；身份与当前位置编号分离。
- `transport.py`：只接受 localhost 模型端点；先保存请求再做分词预检；分词120秒、一次显式重试，推理1800秒、一次显式传输重试，SDK隐式重试关闭。温度0、seed0；所有调用保留请求、响应和token记录。
- `search.py`：搜索动作采用普通JSON及schema校验，再由已有图查询接口执行，解决Qwen复述原生工具反馈的问题。内嵌星号显式按名称模式匹配；方法/函数类型兼容；广泛查询按8节点和12k输入预算分批，最多4页，未处理数明确记录。重复已完成查询有一次纠正机会，不无限重复。
- 相关性判断：B1保留布尔格式，B2/B3使用ID到布尔值的JSON判定；合法部分保留，缺失或冲突项最多纠正一次，剩余项为unknown。B2/B3源码按可读代码块提供，故B1→B2包含输出协议和源码表示的共同变化。
- `causal.py`：B3使用结构化因子、关联操作和因果边。创建与已有因子更新分开约束，新因子ID不复用已有ID；边目标限于issue或已有因子。每个新因子必须有causes因果边，边源隐含为该因子ID；已有因子的目标枚举排除自身，缺乏依据可返回空图。替换代码关联后对新关联继续邻居探索，已展开状态按因子与代码关联去重。
- `runner.py`：固定30题开发与270题验证清单，按历史运行故障和项目取样，不按新命中结果取样。历史工作树只读使用并检查base commit与tracked diff；按版本隔离金丝雀、开发集与全量结果。
- `evaluate.py`、`reports.py`：模型调用之外离线计算原生及共同P/R/F1/SL，另保留历史Top-k。裸函数名只在同文件唯一时映射；多义预测不借助真值选类，仍计入预测数。

## 需要明确记录的行为差异

搜索最多5轮。额外格式纠正、分页、子批次判别分别记账，不能称为与旧版请求数相同。模型输出预算为搜索512、相关性1024、因果4096，均受服务实际剩余上下文限制。

初始因果源码最多4批，每批8个节点；邻居源码最多4批，所有邻居批次共用最多21次更新预算，与旧参数20的实际21次上限对齐。排序采用路径、行号、类型和名称的稳定顺序，未称为置信度排名。

因果输出从Mermaid改为JSON，不是作者原提示词的逐字复现。程序保留模型给出的代码选择，不自动补造因果边、概率或定位。新因子必须给出因果边；结构合法仍不代表原因正确。每个因子最多一个代码关联，GraphLocator的仓库图、邻居探索和优先队列保留。

主方案不引入BM25、CoSIL文件候选或函数功能说明字段。若需要额外回退检索，应另列实验。
