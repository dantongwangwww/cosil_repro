# GraphLocator 本地 Qwen 部署与复现记录

部署目录为 `/mnt/skygruop0/home/wdt/cosil_repro/GraphLocator`，与 `CoSIL` 同级。`/home/wdt/cosil_repro/GraphLocator` 是同一服务器目录的常用路径。

源仓库：[oceaneLIU/GraphLocator](https://github.com/oceaneLIU/GraphLocator)，固定提交 `2bb137cd946f0d29521d2277d6e0f636314e49c0`。README 的 OpenAI/Anthropic 配置统一通过 `llms` 适配为当前本地 Qwen2.5-Coder-7B-Instruct；API 模型名 `llama3` 是原服务别名，未切换模型权重。

## 环境与输入

前端使用独立 `.venv`，Python 3.11.17；作者 README 建议 3.13，但当前 Linux Tree-sitter 动态库使用旧 Python 绑定，3.11 能直接使用兼容 wheel，仓库语法验证通过。按实际运行导入安装最小依赖，避免重装 GPU 服务和庞大的非运行依赖。`deployment/requirements_runtime.txt`、`client_pip_freeze.txt`、`dependency_install.json` 保存依赖要求、实际版本和安装证据。`--system-site-packages` 继承服务器已有基础依赖，因此必须结合 freeze 而非仅凭最小依赖文件复现。安装时提示的部分继承组件版本约束并非当前图搜索客户端的运行依赖；原 CoSIL 模型服务环境未被修改。

数据使用作者 `datasets/swe_bench_lite.jsonl`，与 CoSIL 的 300 个 issue ID、repo、base_commit 和 issue 文本逐项一致。每题从 CoSIL 已缓存的 bare Git 镜像只读克隆到 GraphLocator 的独立工作目录，然后检出该题 base_commit。不同题不会共享可变检出目录。真值仅用于离线报告；修复 patch、测试 patch 和定位真值不进入模型提示词。

原生评分使用作者 `swe_bench_lite_gt_entities_3levels.json`，文件/模块/函数分别适用 300/225/277 题。对齐评分使用 CoSIL 已验证的 `ground_truth_300.json`，函数适用 293 题。两份真值不可混用分母。 离线逐题比对发现 47 题函数目标集合不同，原生无函数真值而共同真值有函数的为 16 题。作者 pytest-5413 和 pytest-5692 两条函数真值使用单冒号并缺少仓库前缀，不符合其输出转换器格式；原生评分保留作者字面值，共同评分独立使用经过验证的真值，差异审计见 `deployment/gold_alignment_audit.json`。

## 修复与影响边界

| 位置 | 原问题 | 本地处理 |
|---|---|---|
| `llms/__init__.py` | 默认外部供应商；缺少源码输入与 token 证据 | 所有角色固定 localhost Qwen；温度/seed 为 0；保存压缩完整请求、响应、用量与错误；实际 tokenizer 验证上下文，不剪 issue/源码 |
| `utils/action_parser.py` | LLM 层返回三元组，解析器按 `.choices` 读取；工具参数可能不是字符串 | 解析实际返回结构；识别声明的原生工具；保持参数字面值和转义 |
| `utils/execute_search.py` | 任意文本 exec、空响应为 None、部分图 API 名称无效、边关系通配符不生效 | 只允许已声明工具的字面量 AST 表达式；空搜索返回空字符串；使用合法邻接 API；通配符遵从原工具说明 |
| `search_agent.py` | 在未响应工具调用后插入用户相关性请求，形成无效工具协议历史 | 相关性判断使用工具调用前的有效历史；工具反馈与原调用对应；保留原相关性选择规则 |
| `utils/convert_results.py` | 绝对路径硬切片；Node 对象与字符串拼接；直接改图节点名称破坏哈希 | 根据仓库路径构造作者真值前缀；复制节点后映射作用域；保留原因果图遍历顺序 |
| `causal_agent.py` | 无出边因子 `max([])` 崩溃；0/负编号误映射列表末尾 | 空出边默认优先级 0；仅接受有效 1-based 编号；越界编号留在原始回答中但不关联代码 |
| Tree-sitter 图生成器 | 104 核机器默认每题开约 20 个进程；每个函数任务重复传完整图 | 环境限制图 worker；只读类/方法阶段每进程绑定一次图，其余会改图的阶段保持原实现 |
| `eval_metric.py` | CLI 属性与参数名不一致；precision 的显示键不一致 | 修复 CLI，使仓库原生评估可运行 |
| 独立运行器 | 作者入口逐题共享工作目录、续跑行为不可靠 | 按 issue 隔离检出；完成和失败原子落盘；中断证据归档；版本冻结后续跑；300 个 ID 对齐聚合 |

工具协议适配有一项显式行为差异：Qwen 若只把 `name/arguments` 工具调用写成文本，允许一次强制原生工具格式重试。原始回答、修复请求和额外 token 分开留档；不把文本伪调用直接执行。除此之外不因准确率调整检索、提示词、候选过滤或因果推理。源码完全保留，剩余上下文不足时只下调输出预算；输入已超过容量的题明确失败。

依赖进程池优化在真实 astropy 图上验证：8 个方法任务的逐边输出及顺序一致，父图没有改变；原映射 18.306 秒，优化 0.340 秒，约 53.8 倍；这个值仅为部署检查中的测量，不代表全实验加速倍率。验证见 `deployment/dependency_pool_equivalence.json`。原始改动前源文件在 `deployment/upstream_snapshot/`，完整差异在 `deployment/local_changes.patch`。

## 保留的作者行为与已知限制

作者 SearchAgent 搜索最多 5 轮、top_k=5；大候选结果才进入 relevance 判断，相关性布尔输出解析保留作者实现。CausalAgent 的 max_turn 参数为 20，但原条件 `turn > max_turn` 可产生 21 次更新，此行为保留并统计实际次数。

Mermaid 解析使用作者严格行格式，普通文字中的定位不自动转为预测。新图会继承既有因子的代码关联，新编号主要映射新因子。初始解析空图时优先队列为空，会直接返回空定位。种子与邻居集合仍按作者实现使用 set，固定 PYTHONHASHSEED=0；没有新增置信度排序。类节点通常是类头，不能按函数体计入源码审计。

原生函数预测使用类限定名称集合，原生 SuccLoc 要求覆盖全部目标。Excel 的 Top-k 兼容 CoSIL 的文件+函数末段名规则，类/变量占位；按文件分组后的实体顺序用于 Top-k。作者没有给出排名分数，该兼容指标不应当成论文原生排名准确率。

## 金丝雀追加修复

第二次验证的原始记录保留在 `results/qwen_300/canary/validated_8a898d63ed/`。astropy 完整通过且优化前后 11 个因果提示词哈希、最终定位一致；Django 在刚构建图的文件节点查询失败，根因是 Location 在生成时采用 str，而 JSON 解码采用 Path，dataclass 相等比较失败，并非代码位置改变。统一 Location 字符串路径为 Path，保留 Node 哈希与实体语义。SymPy 的双通配符搜索引发 ValueError，现将参数错误反馈给对应工具调用，继续原 5 轮，不新增搜索轮数。验证见 `deployment/canary_bug_regression_checks.json`。本地三题准入改为跨已验证副本并行，所有题在修复后的同一版本重新执行；旧通过题不替代新版本验证。

### 大请求运输层修复

并行验证中 SymPy 的相关性判断输入为 23268 token，服务仍在约 10 token/秒地生成，但原 600 秒 HTTP 等待到期后 SDK 隐式重复请求。非流式等待改为 1800 秒，SDK 的 max_retries/num_retries 均设为 0，只保留带错误记录的外层最多 5 次传输尝试。提示词、温度、seed 和 8192 输出上限不变。使用真实客户端检查 read_timeout/max_retries，证据在 `deployment/transport_checks.json`。这次中断前日志完整保存于 `canary/validated_27e0692fa6/`，正式准入重跑全部三题。

## 源码审计的统计边界

工具统计指 SearchAgent 的 search_node/search_edge 查询结果，不把图生成器内部读取过源文件等同于模型已收到源码。FILE/PACKAGE/REPO 节点的 content 通常只是名称，不计为源码；类头、字段赋值与完整函数体分别区分；issue 自带复现代码不算工具提供的仓库源码。主搜索请求、相关性判别请求和因果请求分开核验，工具反馈写入消息缓存但没有后续模型调用也会单独标记。某题主搜索阶段只有文件名、因果阶段实际收到函数体，符合两阶段工作流，不能说整个实验全程没有代码。

正式验证中 SymPy 的相关性模型收到 23268 token，返回 8192 token 的布尔值重复，finish_reason=length，耗时约 774.85 秒。闭合 Markdown 代码块和列表长度检查仍遵从作者实现，不因为答案开头出现 True 就改变筛选规则。该题完整运行并输出文件/类，但函数预测为空；这是模型与格式解析的可观察行为，不作为准确率准入门槛。

## 全量中的兼容恢复

正式批次首次暴露 BODY 查询分支的边数据为 dict，而 edge_deserialization 始终调用 from_json，引发 TypeError。控制器先让已提交任务收尾，再兼容 dict 的 from_dict 解码；正常 JSON 字符串仍走原逻辑，回归测试证明输出完全一致。保存了 48 题已完成预测及 6 题上下文超限记录，唯一受边解析影响的 django-12908 归档后重跑，剩余题续跑。此为兼容部署补丁，不改变模型、检索与因果选择规则。`results/qwen_300/compatible_edge_fix_lineage.json` 记录复用题及逐题文件哈希；旧版版本和故障原文在 `history/v1_before_edge_fix/`。本轮包含修复前后执行批次，报告不声称所有题的Python文件字节哈希完全相同。新版本仍重新执行三题金丝雀，另有真实 BODY 分支离线回归。
