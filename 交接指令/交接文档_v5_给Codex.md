## 〇、一句话总目标与背景

**训练一个小裁判模型（0.6B 级），替换 CoSIL 旧版 pruner 的大模型判决，验证三件事：①判决质量能不能替代（诱饵 precision ≥0.85）；②端到端定位能不能打平基线（函数 Top-5 ≥37.9%）；③速度与成本（单次判决 <0.3s，剪枝 token 降 ≥80%）。**

背景动机（帮你理解为什么这么设计）：我们 900 run 的 v3c 实验已证明现有 pruner 有"语义绑架"病——Qwen 判 True 的案例里大量"文本像 issue 但不是根因"的错留（诱饵）。v5 的科学命题是：**用机械信号标签训练过的小模型，能学会"长得像 ≠ 是因果凶手"**，且比大模型 prompt 判决便宜得多。

## 一、已定决策（不要再改）

| 决策 | 结论 |
|---|---|
| 载体仓库 | **旧版 ZJU-CTAG/CoSIL**（论文版，基线 37.9% 出自它；v3c 900 run 日志同源） |
| 改造点 | `afl/fl/AFL.py` localizer 的 pruner 判决块——即 `code_v3b/AFL_插桩版.py` ~L655 起 `check_res = model.codegen(...)` 处（v3b 插桩就在这里，补丁打同一点） |
| 底座 | **双底座赛马**：Qwen3-Reranker-0.6B（主推）与 Qwen2.5-0.5B-Instruct（对照）同数据同流程都训，赢家当正式裁判 |
| 训练方法 | **只用 SFT+LoRA**（rank16 / lr 5e-5 / 3 epoch）。不做 DPO/GRPO（那是后续升级，见§七） |
| 标签军规 | **禁止 LLM 造标签**。全部标签来自机械信号（gold patch 行号/调用图结构/运行日志） |
| 基线组 | qwen 模式直接复用 v3c off 结果（37.9%），无需重跑 300 题 |
| 对照组 | Decision-1 / Jev 1.13.0 走 API 零样本直连（不训练），当"直接买"基线（见§六） |

**算力纪律**：训练单卡 ~8GB 即可（两个底座都小），与 CSRSE 线错峰（白天它跑/晚上你训，或挑空卡）；**绝不动 vLLM 服务**；参考既有预算管理方式（如 DeepSeek 实验的授权/余额审计）。

## 二、任务 1：造训练数据（五来源）

从既有产物挖矿，产出 `pruner_train/val/test.jsonl`。

**原料**（全在服务器/归档里）：
- v3c 900 run 的 pruner 决策日志（`results/prune_logs_annot/` 下 off/on/shuffled × instance_id 的 jsonl，字段：instance_id/arm/candidate/decision/reason/llm_raw_response/code_snippet_head）；
- gold 真值（base commit AST + patch，函数级金标提取脚本已有，注意用 hunk 头提取法）；
- repo structures（函数源码、调用图——PPR 脚本 `code_v3/ppr_batch.py` 的邻接可复用）；
- 锚点逐题分类 json（e_anchor 用）。

**样本格式**：`{"issue": 截2000字, "function": 截1500字, "label": true/false, "label_source": "A|B|C|D|e_log|e_bm25|e_anchor"}`

**五来源规格**：
- **A 正例**：gold patch 改动的函数（issue+真凶=true）；
- **B 正例**：日志里"成功查询该函数 且 最终定位命中"的案例；
- **C 正例**：gold 函数调用链上下游一跳（用 PPR 邻接算，非 LLM）；
- **D 负例**：gold 文件里 patch 没碰的函数；
- **E 负例（灵魂，三条产线）**：`e_log`=日志里"fetch 了+判 True+∉gold patch"（Qwen 错留现场）；`e_bm25`=issue 全文 BM25 检索本仓库 top-15 函数中非 gold 者；`e_anchor`=issue 点名的函数名中不在 gold patch 者（从锚点 json 正则抽）。

**配比与切分军规（违者返工）**：
1. 正负约 1:2；E 类合计占负例 ≥1/3；
2. **按 instance_id 切 80/10/10**，同题函数绝不跨集（防泄漏——写脚本显式断言）；
3. **一致性过滤**：E 类负例中与 gold 函数有调用边/上下游关系的剔除或改标正例（"长得像"可能真是因果中间站）；
4. B 类中"查询了 gold 但被判 False"的样本标 true（它确实是因果函数，Qwen 判错了）；
5. **test 集封存，只在任务 4 开箱一次**；训练/调参只许看 train/val。

**过关判据**：正例 ≥8000、E 类合计 ≥3000；随机抽 30 条人工核验（E 三族各 10 条），标签错误 ≤2 条；泄漏断言通过。产出统计报告（各来源条数/分布/切分明细）。

## 三、任务 2：双底座训练（赛马制）

**底座 A（主推）：Qwen3-Reranker-0.6B**（ModelScope: `Qwen/Qwen3-Reranker-0.6B`）
- 输入格式走它的原生三段式：instruction（"判断该函数是否在 issue 的因果路径上"）+ query（issue）+ doc（函数代码）；
- 训练目标：**对 yes/no 两个 token 的 logits 做交叉熵**（yes-token 分类），不是生成式输出 JSON——这是它与通用底座的关键差别；
- LLaMA-Factory 若不支持此打分模式，用 transformers 写自定义训练循环（前向取 yes/no logits → CE 损失 → 只回传 LoRA 梯度），预计 50 行内。

**底座 B（对照）：Qwen2.5-0.5B-Instruct**（ModelScope: `Qwen/Qwen2.5-0.5B-Instruct`）
- 标准 chat SFT：instruction 进 prompt，教它输出 `{"verdict": true, "confidence": 0.9}`；对输出 token 序列做交叉熵。

**共同配置**：LoRA rank 16 / target all / lr 5e-5 / 3 epoch / batch 4-8（显存不够用梯度累积凑）/ cutoff 4096。底座全程冻结只训 LoRA。

**每 epoch 体检（val 集）**：accuracy、AUC、**E 类诱饵 precision**（分 e_log/e_bm25/e_anchor 三族报）。val 掉头向下→早停。

**过关判据（资格线）**：val accuracy ≥0.80 且 AUC ≥0.85。**赛马规则（赛前定死）**：主判据 = E 类诱饵 precision；差距 <2pp 平手 → 判底座 A 胜（打分式无格式病+原生概率的架构优势）；败者数据留作底座贡献消融表。**两轮调参后仍 <0.75 → 停止，报告并等指令**（预案：升 1.5B 底座，不自动执行）。

## 四、任务 3：校准与开箱考试

**温度缩放**：胜出模型在 val 上拟合一个温度参数 T（logits/T → softmax），使 P(yes) 数值与真实正确率对齐；再用校准后分布定置信度分层阈值（目标 p>0.9 直判 / 0.6-0.9 灰区 / <0.6 直判——阈值以 val 实测为准，不抄默认）。产出可靠性图（reliability diagram）。

**test 集开箱（唯一一次）**：总体 accuracy/AUC；**分类型精度**（A/B/C/D/E 各报）；**E 类分族 precision**——这是全实验的科学结论数字。

## 五、任务 4：离线三方对线

同一批判决场景（从 v3c 日志抽真实"issue+候选函数"对，含 E 类诱饵子集），三方各判一遍：
1. **自训裁判**（胜出底座）；
2. **Qwen-7B pruner 原版**（复用 v3c 日志判决，不重跑）；
3. **Decision-1 零样本**（微软 API，Foundry 端点；输入构造为"情境+两选项（相关/不相关）"取校准概率。需要申请/确认 API 额度，**预算走既有授权流程**，先估条数×单价报上限再调）。

**报告三个数**：①三方判决一致率；②**E 类诱饵上三方 precision 对比（分族）**——预期 Qwen 大量错留、Decision-1 按语义相似判、自训裁判若 ≥0.85 即命题成立；③三方延迟（自训本地前向 / Qwen ~2s / API 往返）。

## 六、任务 5：插管线 + 金丝雀 + 全量

**补丁**（改造点见§一）：判决函数替换为"小裁判+置信度分层"，环境变量 `PRUNER=small|qwen|hybrid` 三模式（qwen=原版逻辑原样保留，保证对照组可复现）。hybrid：p≥0.9 直判 / 0.6<p<0.9 升级 Qwen 终审 / p≤0.6 直判剪。

**金丝雀**：固定 10 题 × 3 模式 × 2 重复（temp=0 + batch 不变推理 + 与 v3c 同款稳定性检查）。过关：三模式无崩溃、hybrid 的 Qwen 调用数明显少于 qwen 模式、重复间结果一致。

**全量**：300 题 × small/hybrid 两模式（qwen 复用 v3c off）。判分用既有金标脚本（hunk 头提取，勿改口径）。

**双层报告（泄露合规）**：全 300 题成绩 vs 基线 37.9%（注明 240 题参与过裁判训练）；**held-out 60 题子集单独一刀**（基线同子集成绩配对比较）；如时间允许，v4 的 231 题无名池（Verified 挖的、与 Lite 零重叠）做 OOD 一刀。

**最终五线对表**：端到端函数 Top-5（≥37.9%）、单次判决延迟（<0.3s）、剪枝 token 降幅（≥80%，按 v3c 口径对账）、诱饵 precision（≥0.85）、锚点分层子组（gold_named/other_named/no_name 三组报——看裁判在"名字是症状"组是否优于 Qwen）。

## 七、明确不做的事（防自作主张）

- 不做 DPO/GRPO（触发条件：诱饵 precision 落在 0.75-0.85 才上报等指令，不自动补训）；
- 不用任何 LLM 造/改标签；
- 不动 vLLM 服务与 CSRSE 的数据和结果目录；
- 不重跑 qwen 基线 300 题；
- 不改判分口径与金标提取方法；
- test 集不开第二次；所有中间产物（数据统计/训练曲线/校准参数/对线原始输出）落盘归档。
